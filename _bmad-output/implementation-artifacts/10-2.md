# Story 10.2: Widget Staleness Detection & Testing

Status: done

## Story

As a Jeedom user,
I want to know if my widget data is stale,
So that I don't rely on outdated information.

## Acceptance Criteria

1. **Given** widget displayed on dashboard, **When** `collectDate` of `supervision_state` is older than 3× `supervision_interval`, **Then** badge color changes to grey (`text-muted`).

2. **And** label changes to "Données non disponibles" (via i18n `__()` in PHP, injected as placeholder).

3. **And** tooltip on badge explains staleness (e.g., "Dernière mise à jour il y a 2h").

4. **And** staleness check happens on each tile render (client-side, no polling, no `setInterval`).

5. **And** staleness threshold (3×) is consistent with SM1 strike logic (3 missed supervision intervals = problem).

6. **And** mobile widget displays identically to desktop widget (same template, same inline script).

7. **And** integration tests verify:
   - Staleness detection triggers at 3× supervision_interval
   - Badge overrides to grey when stale
   - Fresh data shows normal color-coded badge (green/orange/red)

8. **And** end-to-end: supervision HEALTHY → green badge, DEGRADED → orange, NO_NETWORK → red, zombie daemon → grey after threshold.

## Dev Notes

### Critical Corrections to widget-design.md Task 6.4

**The design doc has TWO errors that MUST NOT be followed:**

1. **Wrong API name:** `widget-design.md` references `jeedom.cmd.getStatsByEqLogicId` — this function does NOT exist in Jeedom. The correct API is **`jeedom.cmd.byEqLogic`** which returns an array of command objects including `collectDate`.

2. **Wrong file placement:** `widget-design.md` shows the staleness code going into `desktop/js/siaDC09.js` with a `$(document).on('cmd::update', ...)` listener. This WILL NOT WORK because `siaDC09.js` is only loaded on the plugin **configuration page**, never on the dashboard. The correct approach is an **inline `<script>` block** in the HTML template file (`core/template/dashboard/siaDC09.html`).

### Why Inline `<script>` Works

When `cmd::update` fires on the dashboard, Jeedom's core JS:
1. Calls `toHtml()` on the backend via AJAX
2. Replaces the tile's entire DOM with the new HTML
3. The inline `<script>` in the new HTML executes immediately after DOM insertion

This means the stale check runs automatically on:
- **Initial page load** — script in server-rendered HTML executes
- **Every `cmd::update` for this eqLogic** — tile DOM replaced, new script executes

**No explicit `cmd::update` listener is needed.** The re-render mechanism handles it.

### The Zombie Daemon Scenario (Primary Use Case)

When the daemon dies silently (zombie):
1. No `checkAndUpdateCmd()` → no `cmd::update` → no tile re-render
2. User opens dashboard → tile served from `preToHtml()` cache (shows last known state, e.g. green)
3. Inline `<script>` executes on page load → fetches `collectDate` via `jeedom.cmd.byEqLogic`
4. `collectDate` is old → staleness detected → badge overridden to grey + "Données non disponibles"

**Accepted limitation:** If user has dashboard open and daemon dies AFTER page load, tile stays green until next page refresh. The `cron5()` watchdog is the primary safety mechanism (sends SMS/push notifications).

### `jeedom.cmd.byEqLogic` API (Authoritative)

```javascript
jeedom.cmd.byEqLogic({
    eqLogic_id: eqLogicId,
    success: function(cmds) {
        // cmds = array of command objects
        // Each cmd has: id, logicalId, name, type, subType, value, collectDate, ...
        // collectDate format: "YYYY-MM-DD HH:MM:SS" (server local time)
    }
});
```

### Inline Script Implementation

The script goes at the bottom of the HTML template, inside the root `<div>`:

```html
<script type="text/javascript">
(function() {
    var rootEl = document.querySelector('[data-eqLogic_id="#id#"].siaDC09');
    if (!rootEl) return;
    var eqId = '#id#';
    var interval = parseInt('#supervision_interval#', 10) || 60;
    var staleThreshold = interval * 3;

    jeedom.cmd.byEqLogic({
        eqLogic_id: eqId,
        success: function(cmds) {
            var stateCmd = null;
            for (var i = 0; i < cmds.length; i++) {
                if (cmds[i].logicalId === 'supervision_state') {
                    stateCmd = cmds[i];
                    break;
                }
            }
            if (!stateCmd || !stateCmd.collectDate) return;

            var collectTime = new Date(stateCmd.collectDate.replace(/-/g, '/')).getTime();
            var staleSince = (Date.now() - collectTime) / 1000;

            if (staleSince > staleThreshold) {
                var badge = rootEl.querySelector('.siaDC09-badge');
                var label = rootEl.querySelector('.siaDC09-label');
                if (badge) {
                    badge.classList.remove('text-success', 'text-warning', 'text-danger');
                    badge.classList.add('text-muted');
                    var minutes = Math.floor(staleSince / 60);
                    var hours = Math.floor(minutes / 60);
                    var tooltip = '#stale_tooltip_prefix# ';
                    if (hours > 0) {
                        tooltip += hours + 'h' + (minutes % 60 > 0 ? String(minutes % 60).padStart(2, '0') : '');
                    } else {
                        tooltip += minutes + ' min';
                    }
                    badge.setAttribute('title', tooltip);
                }
                if (label) {
                    label.textContent = '#stale_label#';
                }
            }
        }
    });
})();
</script>
```

**Key implementation details:**
- IIFE wrapping prevents variable leaks (multiple siaDC09 tiles on same dashboard)
- `#id#` and `#supervision_interval#` are server-injected by `template_replace()` — they become literal values
- `#stale_label#` and `#stale_tooltip_prefix#` are i18n-wrapped strings from `toHtml()`
- `new Date(collectDate.replace(/-/g, '/'))` — Safari/older browsers fail on `YYYY-MM-DD` format with dashes
- No jQuery dependency — uses vanilla JS `querySelector` (but `jeedom.cmd.byEqLogic` uses jQuery internally, which is fine since Jeedom loads jQuery on all pages)
- No `setInterval` — runs once per render, which is sufficient

### Null Edge Cases

| Scenario | `collectDate` | Staleness check result |
|---|---|---|
| Commands not yet created (first boot) | `getCmd()` returns null → `byEqLogic` returns empty or no `supervision_state` | Script returns early (no override) |
| Daemon just started, first supervision pending | `collectDate` = recent (from `postSave` initial value) | Not stale — shows INITIALIZING (orange) |
| Daemon healthy | `collectDate` updated every supervision cycle | Not stale — shows normal badge |
| Daemon dead > 3× interval | `collectDate` old | STALE — grey badge + "Données non disponibles" |
| Equipment disabled | `toHtml()` already renders grey + "Désactivé" | Script runs but `text-muted` already set — no visual change (harmless) |

### i18n Compliance

Three new strings in `toHtml()` require i18n wrapping:
- `__('Données non disponibles', __FILE__)` — stale label
- `__('Dernière mise à jour', __FILE__)` — tooltip prefix

These will be auto-discovered by Jeedom's i18n scanner.

### What NOT To Do

- Do NOT put JS code in `desktop/js/siaDC09.js` — it doesn't run on dashboard
- Do NOT use `jeedom.cmd.getStatsByEqLogicId` — that function does not exist
- Do NOT use `setInterval`/`setTimeout` for periodic polling — one-shot on render is sufficient
- Do NOT use `$(document).on('cmd::update', ...)` — unnecessary because tile re-renders handle it
- Do NOT create a separate JS file for the widget — inline script in template is the Jeedom pattern
- Do NOT modify `desktop/js/siaDC09.js` — no changes needed
- Do NOT use `execCmd()` or any server-side value fetching from JS — `jeedom.cmd.byEqLogic` is purely client-side cache/DB read
