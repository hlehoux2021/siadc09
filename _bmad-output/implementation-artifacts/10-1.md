# Story 10.1: Widget Rendering & Bootstrap Panel

Status: done

## Story

As a Jeedom user,
I want to see my monitoring connection status on the dashboard,
so that I can verify monitoring is active at a glance.

## Acceptance Criteria

1. **Given** equipment added to dashboard, **When** dashboard loads, **Then** widget displays Bootstrap 3 panel with supervision status badge + label and last event info.

2. **And** panel header shows color-coded badge:
   - Green (`text-success`): `supervision_state=2` (HEALTHY)
   - Orange (`text-warning`): `supervision_state=1` (DEGRADED 1-2, INITIALIZING)
   - Red (`text-danger`): `supervision_state=0` (DEGRADED 3, TCP_RECONNECTING, NO_NETWORK, STOPPED)
   - Grey (`text-muted`): null (commands not yet initialized) or equipment disabled

3. **And** human-readable `supervision_label` displayed next to badge (daemon-provided French string).

4. **And** last event section shows `event_label` (daemon-formatted string) or default "Aucun événement depuis le démarrage".

5. **And** equipment disabled state (`getIsEnable() === 0`) overrides all — shows grey badge + "Désactivé".

6. **And** widget HTML template is identical for desktop and mobile.

7. **And** widget refreshes via standard Jeedom `cmd::update` → re-call `toHtml()` mechanism (no custom JS needed).

8. **And** Bootstrap 3 styling consistent with Jeedom UI.

9. **And** all user-facing strings use `__('text', __FILE__)` i18n calls — no hardcoded French in PHP.

## Dev Notes

### Existing Code State (siaDC09.class.php)

The `siaDC09` eqLogic class at `core/class/siaDC09.class.php` already has:
- `postSave()` creating 4 INFO commands: `supervision_state` (numeric), `supervision_label` (string), `event_state` (numeric), `event_label` (string) — all with `isVisible=0`
- `postSave()` creating 3 ACTION commands: `burglarAlarm`, `fireAlarm`, `panicAlarm` — all with `isVisible=0`
- Static methods: `deamon_info()`, `deamon_start()`, `deamon_stop()`, `cron5()`, `sendToDaemon()`, `message()`
- Private: `_getAutoEquipment()`, `_getAutoEquipmentSafe()`, `_handleInfoUpdate()`, `_checkSupervisionFreshness()`

**Add `toHtml()` as an instance method** after the static methods, before `postSave()`. Signature: `public function toHtml($_version = 'dashboard')`.

### Architecture Constraints (MUST FOLLOW)

1. **`toHtml()` contains no hardcoded French** — all user-facing text via `__('key', __FILE__)` i18n calls [Source: architecture.md line 1073]
2. **Use `getValue()`** — reads last DB value written by `checkAndUpdateCmd()`. Never `execCmd()` in `toHtml()`.
3. **No stale detection in PHP** — that's story 10-2 (JS-side). `preToHtml()` caching makes PHP stale checks unreachable in zombie daemon scenario.
4. **Same template for desktop and mobile** — Bootstrap 3 panels are fluid-width.
5. **`data-supervision-interval`** attribute embedded for story 10-2 JS to read without extra AJAX.
6. **All commands `isVisible=0`** — `toHtml()` is the only display mechanism; no individual cmd widgets on tile.

### Jeedom `toHtml()` API (authoritative)

```php
public function toHtml($_version = 'dashboard') {
    // 1. Cache check — returns cached HTML string if tile unchanged; else returns $replace array
    $replace = $this->preToHtml($_version);
    if (!is_array($replace)) {
        return $replace;
    }

    // 2. Add custom placeholders to $replace array
    $replace['#my_placeholder#'] = $value;

    // 3. Load template file
    //    getTemplate('core', $_version, 'siaDC09', 'siaDC09')
    //    → reads: core/template/{$_version}/siaDC09.html from plugin 'siaDC09'
    //    Params: (string $type, string $version, string $template, string $pluginId)

    // 4. Substitute and return
    return $this->postToHtml(
        $_version,
        template_replace($replace, getTemplate('core', $_version, 'siaDC09', 'siaDC09'))
    );
}
```

**`$replace` pre-populated by `preToHtml()`:** `#id#`, `#name#`, `#version#`, `#eqLink#`, `#eqType#`, `#uid#`, `#object_name#`, `#hideCmdName#`, etc. You add your custom `#badge_class#`, `#supervision_label#`, `#event_label#`, `#supervision_interval#`.

**Live update cycle (no custom JS):**
1. Daemon calls `checkAndUpdateCmd()` on INFO commands
2. Jeedom fires `cmd::update` websocket event
3. Dashboard JS detects update → re-requests tile HTML via `toHtml()` AJAX call
4. Tile re-renders with current values

### `toHtml()` PHP Implementation

```php
public function toHtml($_version = 'dashboard') {
    $replace = $this->preToHtml($_version);
    if (!is_array($replace)) {
        return $replace;
    }

    $supervisionStateCmd = $this->getCmd('info', 'supervision_state');
    $supervisionLabelCmd = $this->getCmd('info', 'supervision_label');
    $eventLabelCmd       = $this->getCmd('info', 'event_label');

    $stateValue = ($supervisionStateCmd) ? intval($supervisionStateCmd->getValue()) : null;
    $labelValue = ($supervisionLabelCmd) ? $supervisionLabelCmd->getValue()          : '';
    $eventValue = ($eventLabelCmd)       ? $eventLabelCmd->getValue()                : '';

    if ($this->getIsEnable() === 0) {
        $replace['#badge_class#']       = 'text-muted';
        $replace['#supervision_label#'] = htmlspecialchars(__('Désactivé', __FILE__));
    } else {
        if ($stateValue === null) {
            $replace['#badge_class#']       = 'text-muted';
            $replace['#supervision_label#'] = htmlspecialchars('—');
        } elseif ($stateValue === 2) {
            $replace['#badge_class#']       = 'text-success';
            $replace['#supervision_label#'] = htmlspecialchars($labelValue ?: '—');
        } elseif ($stateValue === 1) {
            $replace['#badge_class#']       = 'text-warning';
            $replace['#supervision_label#'] = htmlspecialchars($labelValue ?: '—');
        } else {
            $replace['#badge_class#']       = 'text-danger';
            $replace['#supervision_label#'] = htmlspecialchars($labelValue ?: '—');
        }
    }

    $replace['#event_label#'] = htmlspecialchars(
        $eventValue ?: __('Aucun événement depuis le démarrage', __FILE__)
    );

    $replace['#supervision_interval#'] = (int) $this->getConfiguration('sia_supervision_interval', 60);

    return $this->postToHtml(
        $_version,
        template_replace($replace, getTemplate('core', $_version, 'siaDC09', 'siaDC09'))
    );
}
```

### Null Edge Cases

| Scenario | `supervision_state` | Badge | Label |
|---|---|---|---|
| Commands not yet created (first boot before `postSave()`) | `getCmd()` returns null | `text-muted` | "—" |
| Equipment disabled | any | `text-muted` | "Désactivé" |
| Daemon not yet started (initial value from `postSave()`) | `1` | `text-warning` | "DÉMARRAGE…" |
| HEALTHY | `2` | `text-success` | daemon label |
| DEGRADED strikes 1-2, INITIALIZING | `1` | `text-warning` | daemon label |
| DEGRADED strike 3, TCP_RECONNECTING, NO_NETWORK, STOPPED | `0` | `text-danger` | daemon label |

### i18n Compliance

Two strings in `toHtml()` require i18n wrapping:
- `__('Désactivé', __FILE__)` — equipment disabled label
- `__('Aucun événement depuis le démarrage', __FILE__)` — default empty event

These will be auto-discovered by Jeedom's i18n scanner and added to `core/i18n/*.json` files. Existing i18n files (`en_US.json`, `de_DE.json`, `es_ES.json`, `it_IT.json`, `pt_PT.json`) exist but are NOT modified by this story — Jeedom handles translation at runtime.

### What NOT To Do

- Do NOT add any custom JavaScript for widget rendering — standard Jeedom handles everything
- Do NOT add `addCmdToObject` — that function does not exist in Jeedom
- Do NOT add `setInterval`/`setTimeout` for polling — updates come via `cmd::update` websocket
- Do NOT perform stale detection in `toHtml()` — unreachable in zombie daemon case; that's story 10-2
- Do NOT create a separate CSS file — Bootstrap 3 classes are sufficient
- Do NOT use `execCmd()` — always `getValue()` for display
- Do NOT modify `desktop/js/siaDC09.js` — no JS changes needed for this story
